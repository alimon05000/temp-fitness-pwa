# Архитектура

## Размещение

Frontend — React 19, strict TypeScript, Vite. Статический `dist/` публикуется GitHub Actions в Pages владельца `alimon05000`. Пользователь явно исключил ChatGPT Sites. На GitHub Pages невозможно исполнять serverless API, поэтому `worker/index.ts` работает отдельно на Cloudflare Workers. Постоянный атомарный бюджет принадлежит SQLite Durable Object `CoachQuota`. `api/coach.ts` — запасной Node adapter, в текущем размещении не используется. Все базовые сценарии работают при полном отсутствии backend.

## Модель и хранение

`src/domain.ts` задаёт Zod DTO и типы: профиль, цели, упражнения, блоки, шаблоны, расписание, сессии, результаты, сообщения и предложения. ID — `crypto.randomUUID()`, даты занятий — локальные YYYY-MM-DD, системные метки — epoch milliseconds, время результата — числовые секунды, расстояние — метры, вес — кг. Рекорды вычисляются из завершённых записей, не дублируются в изменяемой таблице.

Dexie/IndexedDB `temp-fitness-v1`, version 1, таблица `snapshots`, ключ `main`. Весь согласованный снимок сохраняется одной атомарной записью. Последовательная очередь не позволяет старой записи затереть новую. Это упрощает локальный режим и JSON backup; для десятков тысяч занятий требуется переход на отдельные indexed tables. На каждой границе есть ограничения размера/чисел/дат и версия формата. Миграция будущей версии должна добавляться явно; неизвестная версия не перезаписывается.

При ошибке записи показано предупреждение и доступен экспорт состояния из памяти. Несколько вкладок одновременно не поддерживают согласование изменений. Cloud SyncMetadata, Auth и серверные пользователи намеренно отсутствуют, поскольку Supabase не сконфигурирован. Нет fake auth.

## Тренировка

Занятие получает снимок блоков шаблона. Изменение/удаление упражнений и шаблонов не изменяет завершённую историю. Статусы: `running`, `paused`, `completed`, `cancelled`; запланированное занятие — отдельная запись календаря.

`elapsedMs + (now - resumedAt)` считает активное время. `stageMs`, `stageAt` отвечают за этап, `restUntil` — за отдых. При паузе сохраняются накопленное время и остаток отдыха. При возобновлении метки пересоздаются. setInterval только перерисовывает интерфейс. На iOS закрытие приложения не гарантирует фонового звука; после открытия время пересчитывается.

Бег: каждая запись — независимый сплит; личный рекорд 1 км требует ровно 1000 м, не экстраполируется из 400 м. Подтягивания: максимум — один подход без дополнительного веса; общий объём — сумма. При удалении/исправлении фактов аналитика вычисляется заново.

## Навигация и UI

Hash navigation сохраняет Back и не требует server rewrite на Pages. Общие компоненты, дизайн-токены, адаптивные сетки, системные шрифты без удалённых загрузок, Lucide, Recharts. Четыре mobile-вкладки плюс календарь/ИИ/настройки в шапке; desktop sidebar. Modal имеет начальный фокус, возврат фокуса, Tab-trap и Escape. Reduced motion, safe-area и touch targets поддержаны.

## PWA

Build-script генерирует manifest и service worker из фактических assets с версией содержимого и scope, соответствующим `VITE_BASE_PATH`. Все ресурсы precached. Навигация — network-first с app shell fallback; известные immutable assets — cache-first, `ignoreVary` для одинаковых публичных assets. API и сторонние запросы не кэшируются. Изменение версии очищает только кэши собственного scope, IndexedDB не трогает. Новая версия применяется кнопкой; незаписанное состояние блокирует обновление.

## Облако в будущем

Для Supabase потребуется user_id на каждой сущности, RLS `auth.uid() = user_id`, собственные ревизии/тombstones, исходящая очередь и конфликтное копирование записей. Не добавляйте облако одним сохранением общего JSON без RLS/ревизий. Перед первым входом делайте backup, затем импортируйте локальную историю как новые записи. Эти функции не заявлены работающими.
