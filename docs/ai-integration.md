# ИИ-тренер

## Статус

Модель — `gpt-6.1-sol`, провайдер — `https://tooken.club/v1/chat/completions`. Реальный короткий запрос напрямую провайдеру прошёл с HTTP 200, подтверждённой моделью и 35 токенами суммарно. Затем прошёл отдельный реальный запрос через размещённый Worker: HTTP 200, корректный CORS, модель `gpt-6.1-sol` и валидное предложение из одного дня.

Текущий backend — Cloudflare Workers, не Vercel. HTTPS endpoint доступен, `/health` отвечает `ready`; результаты — в [QA](qa-checklist.md). Без доступного ИИ дневник остаётся работоспособным.

## Граница доверия

Browser → HTTPS Cloudflare `/api/coach` → Tooken. Ключ хранится в Workers Secrets. Header `X-Coach-Access` содержит отдельный случайный код владельца (не меньше 32 символов). Он живёт в памяти вкладки, не попадает в JSON backup или IndexedDB. Для полноценного многопользовательского продукта замените его индивидуальной авторизацией и отдельными квотами.

CORS допускает только `https://alimon05000.github.io`. Хеши кода сравниваются побайтно без раннего выхода. Durable Object хранит постоянную глобальную квоту: 5 запросов в минуту, 50 в сутки. Атомарная транзакция защищает от параллельных запросов; ошибка лимитера закрывает платные вызовы. Счётчики не содержат персональных данных. Установите бюджет также на стороне Tooken: число запросов не равно денежному бюджету.

Тело читается потоком до 32 KB, вопрос ограничен 1500 символами, последние 6 сообщений — 2000 символов каждое. Провайдеру разрешено до 3500 output tokens, timeout — 30 секунд. Автоматических повторных платных запросов нет. Ошибки upstream не возвращают его body/ключи; приложение не логирует тренировочные подробности. Workers Observability отключена в конфигурации; техническая обработка запросов платформой регулируется её условиями.

## Структурированные планы

`server/contracts.ts` содержит общие схемы запроса/ответа. Пользовательская история — недоверенные данные, не системные инструкции. Ответ проверяется Zod. HTML/JS из ответа не исполняется. План остаётся предложением до нажатия «Принять план». Кнопка применяет типизированные блоки к календарю ровно один раз; отклонение не меняет календарь. ИИ не диагностирует и не обещает фиксированный срок результата.

## Согласие и контекст

По согласию передаются цели, число подходов, отдых, частота/длительность, уровень, оборудование и введённые ограничения нагрузки. По отдельному разрешению — до 10 последних тренировок: результаты, RPE и самочувствие. Имя, GPS и заметки не передаются. Последние 6 сообщений чата передаются как история; не вводите туда данные, которые не хотите отправлять.

Отключение согласия блокирует запросы. Удаление чата очищает локальные сообщения, но не отзывает уже переданные данные у провайдера.

## Настройка

Инструкция: [Cloudflare](cloudflare.md). Обязательные secrets: `TOOKEN_API_KEY`, `COACH_ACCESS_CODE`. Публичные vars: `TOOKEN_BASE_URL`, `TOOKEN_MODEL`, `ALLOWED_ORIGIN`. Публичная frontend-переменная `VITE_COACH_API_URL` содержит только URL.

`api/coach.ts` — альтернативный Node adapter с Redis-квотами. Он сохранён для переносимости, не развёрнут в Vercel и не нужен текущему Cloudflare варианту.

## Проверки

Автоматические тесты проверяют согласие, размер, CORS, код, отсутствие настроек, квоты, валидный/невалидный ответ провайдера. E2E использует только mock `coach.example` для проверки интерфейса и границы принятия плана. Mock не выдаётся за работающий production AI.
