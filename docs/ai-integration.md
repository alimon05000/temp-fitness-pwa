# ИИ-тренер

## Реальный статус

Реальный Tooken-запрос не выполнен: серверный ключ и развёрнутый endpoint отсутствуют. Модель по умолчанию — `gpt-6.1-sol`, endpoint — `https://tooken.club/v1/chat/completions`. Формат OpenAI-compatible JSON проверяется схемой. Совместимость конкретного Tooken-аккаунта проверяется после настройки реальным коротким запросом из чата; успех — 200 и валидный ответ с моделью. Нельзя считать mock-тест проверкой провайдера.

## Граница доверия

Browser → HTTPS `/api/coach` на отдельном сервере → Tooken. В браузер не попадает Tooken API key. Header `X-Coach-Access` содержит отдельный высокоэнтропийный код владельца, который не хранится в IndexedDB и экспортируемом JSON. Код не предназначен для публичного многопользовательского сервиса; для такого сервиса замените его индивидуальной авторизацией и пользовательскими квотами.

Без API key, access code или production Redis endpoint закрывается 503. CORS разрешает только заданный `ALLOWED_ORIGIN`, без wildcard. Код сравнивается через SHA256 + timingSafeEqual. Redis MULTI/EXEC INCR + EXPIRE обеспечивает атомарную минутную и суточную квоты между serverless-инстансами. Ошибка Redis закрывает платный маршрут. Локальная in-memory реализация разрешена только вне production.

Тело ограничено 32 KB, вопрос 1500 символами, последние 6 сообщений — 2000 символов каждое. Провайдер ограничен 3500 output tokens, 30 секунд таймаута. Запросы не повторяются автоматически, чтобы избежать повторной оплаты. Ошибки провайдера возвращаются без response body upstream и без секретов. Персональные подробности не логируются приложением.

Система запрещает исполнять инструкции внутри недоверенного контекста. План валидируется Zod; только типизированное предложение может попасть в календарь, исключительно по «Принять план». Отклонение не меняет расписание. Текст ответа не исполняется как HTML/JS. План не является медицинской рекомендацией.

## Минимальный контекст

По согласию: цели, предпочтение подходов/отдыха/частоты/длительности, опыт, оборудование и введённые ограничения нагрузки. По отдельному разрешению — до 10 последних занятий с результатами, RPE и самочувствием. Имя, GPS и заметки не входят. Последние 6 сообщений чата передаются как история: не вводите туда данные, которые не хотите передавать.

Отключение согласия блокирует запросы; очистка чата удаляет локальные сообщения. Удаление уже отправленных данных у провайдера зависит от его условий и настроек; локальное удаление не отзывает совершённый запрос.

## Серверные переменные

`TOOKEN_API_KEY`, `TOOKEN_BASE_URL`, `TOOKEN_MODEL`, `COACH_ACCESS_CODE`, `ALLOWED_ORIGIN`, `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`. Настраивать в Vercel Settings → Environment Variables, затем redeploy. Не хранить реальные значения в репозитории или GitHub Pages.

Публичная переменная frontend `VITE_COACH_API_URL` содержит только URL. Секретов под `VITE_*` не должно быть.

## Тестирование

Unit/API-тесты подменяют fetch провайдера и проверяют 503 без ключа, 401 без кода, 403 для постороннего origin, обязательное согласие, предел длины, валидный JSON и отказ от невалидного плана. E2E подменяет только тестовый URL `coach.example` и проверяет, что до принятия план не записан.
