# ТЕМП — в своём ритме

Устанавливаемый дневник тренировок на русском: бег, подтягивания, произвольные упражнения, цели, календарь и аналитика из реальных записей. Основные функции работают без регистрации и без интернета после первой загрузки.

**Приложение:** https://alimon05000.github.io/temp-fitness-pwa/  
**Исходники:** https://github.com/alimon05000/temp-fitness-pwa

Репозиторий публичный с явного разрешения владельца. GitHub Actions успешно выполнил проверки и публикацию. ChatGPT Sites не используется. Сервер ИИ подготовлен в Cloudflare Workers, без Vercel и отдельного Redis.

## Возможности

- Цели: числовой исходный результат, цель, направление улучшения; изменение и удаление.
- Бег: контрольный 1 км, интервалы (включая 5 × 400 м), лёгкий/темповый бег, произвольные этапы по времени или дистанции, ручная запись, темп мин/км.
- Подтягивания: N подходов, максимум без веса, лестница, дополнительный вес; факт по подходам, RPE, техника. Сумма повторений и максимум одного подхода разделены.
- Активная тренировка: пауза, отдых, дополнительные/пропущенные этапы, исправления, итог и отмена. Время рассчитывается по меткам, незавершённое занятие восстанавливается.
- Каталог с поиском и фильтрами; свои категории/упражнения; смешанные шаблоны, копирование, порядок и отдых; история содержит независимые снимки упражнений.
- Календарь: добавить, перенести, заменить, пропустить и начать занятие.
- Аналитика: периоды, реальные графики и таблицы, рекорды, частота, объём, выполнение плана, сравнение количества занятий с предыдущим периодом. Нет выдуманных прогнозов.
- JSON backup/import с проверкой схемы, CSV с защитой от формул, редактирование/удаление истории. Перед удалением/импортом скачивается копия.
- Светлая/тёмная/системная тема, safe-area, четыре основные вкладки, desktop-навигация, поддержка reduced motion и клавиатуры.
- PWA manifest, иконки 192/512/maskable, полный app shell в кэше, ручное применение обновлений без очистки базы.
- Отдельный серверный ИИ endpoint: Tooken, `gpt-6.1-sol`, проверка согласия, CORS, код доступа, квоты, Zod-валидация, применение предложений только по кнопке.

## Запуск на Windows

Требуется Node.js 22.12+ (проверено на 24).

```powershell
cd '
npm run dev
```

Откройте адрес из терминала. Для настоящей проверки PWA используйте production preview:

```powershell
npm run build
npm run preview
```

Service worker намеренно не включается в dev-режиме. Сборка не требует API-ключей. Никогда не открывайте `dist/index.html` через `file://`: нужен HTTP(S)-сервер.

## GitHub Pages

Интерфейс написан на React + TypeScript + Vite. Этот выбор позволяет размещать всё приложение по GitHub-ссылке; Next.js сервер на GitHub Pages не запускается. Отдельная Node serverless-функция находится в `api/coach.ts`.

В workflow `.github/workflows/ci.yml` уже настроены lint, typecheck, unit/component/API tests, build, secret scan, Playwright и Pages deployment. В настройках репозитория выберите **Settings → Pages → Source: GitHub Actions**. Базовый путь определяется автоматически по имени репозитория. Для пользовательского репозитория `alimon05000.github.io` используется `/`, для проектного — `/<имя>/`.

GitHub Free позволяет Pages из публичных репозиториев; Pages из private требует подходящего платного плана. Исходники остаются private по умолчанию. Не меняйте видимость без разрешения владельца. Это ограничение GitHub, а не приложения: [документация GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages).

После входа **именно как `alimon05000`**, при установленном GitHub CLI:

```powershell
gh auth login --hostname github.com --git-protocol https --web
gh api user --jq .login
# Продолжайте только если команда выше вывела alimon05000.
gh repo create alimon05000/temp-fitness-pwa --private --source . --remote origin
git push -u origin main
```

Уже созданный репозиторий повторно не создавайте. URL фактически опубликованного сайта смотрите в успешном задании `deploy`. По умолчанию публикация в ветку `main` запускает CI.

## ИИ без утечки ключа

Основной backend — **Cloudflare Workers + SQLite Durable Object**, доступные на Free-плане. Vercel не используется. Приложение открывается по GitHub Pages; к Workers обращается только чат.

- Сервер: `https://temp-fitness-coach.temp-fitness-pwa.workers.dev/api/coach`.
- Модель: `gpt-6.1-sol`, провайдер `https://tooken.club/v1/chat/completions`.
- Реальный короткий запрос напрямую к провайдеру прошёл: HTTP 200, модель подтверждена, 35 токенов суммарно. Дополнительно прошёл реальный вызов через публичный Cloudflare endpoint: HTTP 200, модель подтверждена, валидное предложение из одного дня. `/health` отвечает `ready`.
- Ключ установлен в Cloudflare Workers Secrets, отсутствует в исходниках и browser bundle.
- Лимиты — атомарные, постоянные: 5 запросов в минуту и 50 в сутки на весь сервис. Сбой лимитера закрывает платный маршрут. Идентификаторы пользователей и тренировки в Durable Object не хранятся.
- Для чата включите согласие в настройках и введите **отдельный код доступа**, а не ключ Tooken. Код живёт только в памяти вкладки. Локальная копия кода владельца защищена Windows DPAPI вне репозитория.
- При ошибке HTTPS или сервера чат показывает недоступность, дневник остаётся рабочим. Текущий статус проверок: [QA checklist](docs/qa-checklist.md).

Развёртывание на своём Cloudflare-аккаунте и безопасная замена ключа: [Cloudflare setup](docs/cloudflare.md). API-контракт: [ИИ-интеграция](docs/ai-integration.md). `api/coach.ts` оставлен как альтернативный Node/Vercel adapter, но не используется в текущем размещении.

`.env.example` — безопасный шаблон. Нельзя задавать Tooken key в `VITE_*` или `NEXT_PUBLIC_*`. Если ключ передавался в чате, перевыпустите его для постоянного использования.

## Установка и офлайн

- Android/Chromium: кнопка «Установить ТЕМП» или меню браузера → Установить приложение.
- iPhone: откройте HTTPS-сайт в Safari → Поделиться → На экран «Домой».
- Сначала дождитесь подписи **«Готов к работе офлайн»**. После этого можно отключить сеть, перезагрузить, смотреть историю и вести занятия.
- HTTPS обязателен вне localhost. Установка на физический iPhone/Android ещё не проверялась.
- iOS/браузер может приостанавливать JavaScript, GPS и звуки в фоне. При возвращении таймер восстанавливает длительность; точный фоновый сигнал не обещается.
- GPS запрашивается только кнопкой и показывает примерную дистанцию/временный маршрут. Маршрут не сохраняется и не передаётся ИИ. Он не равен официально измеренной дистанции.
- Данные привязаны к браузеру и origin. Переезд с localhost на GitHub Pages не переносит записи автоматически: используйте JSON export/import.

## Что пока не подключено

Нет облачной синхронизации, аккаунтов и Supabase: локальный режим не имитирует вход. Данные не синхронизируются между устройствами/вкладками; пользуйтесь одной вкладкой. Нет гарантированных фоновых push-уведомлений, серверных напоминаний, автоматического прогноза целей и медицинской оценки восстановления. Сохраните резервную копию перед очисткой данных браузера.
